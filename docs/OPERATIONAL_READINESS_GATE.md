### فحص المتصفح

| النماذج والملفات | POST/PUT/DELETE وFormData تحمل nonce؛ تدفقات التواصل والمتابعة والقبول تحفظ مرة واحدة؛ لا حاجة لأي رفع جديد |

### التراجع

عند فشل فحص التطبيق قبل الدمج، أبقِ main السابق وأوقف اعتماد المرشح. `0046` تغيّر التشخيص فقط وهي متوافقة مع الكود السابق؛ لا تستعد قاعدة كاملة فوق كتابات أحدث لمجرد الرجوع بكود الواجهة. إذا ظهر فقد بيانات، أوقف الكتابة وحدد الفارق ووقت الاستعادة ومسؤول القرار قبل أي restore بعيد. العودة إلى واجهة Bearer القديمة تتطلب دخولًا جديدًا؛ إلغاء cookies الحالية وتوثيق الاستجابة جزء من خطة التراجع.

## سياسة النسخ المقترحة للتشغيل

هذه خطة جاهزة للتنفيذ، وليست مهمة مجدولة مفعلة. تحدد المدرسة مسؤولًا وبديلًا ومكان حفظ خاصًا مشفرًا قبل بدء pilot. المقترح: نسخة يومية وقبل كل migration، احتفاظ بآخر 7 نسخ يومية و4 أسبوعية ونسخة ما قبل التغيير حتى إغلاقه، والتحقق من بصمة كل نسخة وتجربة restore معزولة شهريًا وبعد تغيير schema. الهدف المقترح RPO ≤24h وRTO ≤4h ويجب قياسه قبل اعتماده. راجع سعة موقع الحفظ قبل تفعيل الاحتفاظ ولا تحذف نسخة موجودة آليًا بهذا المستند.

يشمل سجل النسخ target IDs وSHA الكود ووقت البداية/النهاية والحجم وSHA-256 وسجل migrations ونتيجة المقارنة الدقيقة وFK. تُسجل استعادة R2/وجود objects واتساقها مع D1 كفحص مستقل؛ تصدير D1 لا يحتوي ملفات R2. لا توضع الأسرار أو SQL الخاص أو أسماء الطلاب في Git/Notion، ولا ينشأ bucket أو رفع جديد ضمن هذا العمل.
