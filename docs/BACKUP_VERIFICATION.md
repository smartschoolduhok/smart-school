# التحقق المحلي من النسخ الاحتياطية

الحالة: أدوات محلية للتحقق فقط. لا توجد مهمة نسخ يومية مفعلة بهذه الحزمة، ولا وجهة حفظ جديدة أو حساب خدمة أو تشفير للنسخ. لا اتصال بقاعدة بعيدة، ولا قراءة لاعتماديات Cloudflare، ولا رفع R2 أو حذف ملفات. تبقى وجهة الحفظ المشفرة وهوية التشغيل والجدولة والتنبيه مدخلات تشغيل مستقلة.

الأوامر تعمل على Node.js 24 بعد `npm ci` وتقرأ نسخة SQL سبق الحصول عليها بالإجراء المعتمد. جميع المدخلات والمخرجات الخاصة خارج أي Git checkout، بما فيها المسارات التي تمر عبر symlink أو junction. يجب وجود المجلد الأب، ويُرفض استبدال ملف موجود.

## الملفات والثقة

ملف `target.json` مستقل يحدد الهوية المتوقعة؛ لا يستنتج الأمر الهوية من اسم الملف أو إعدادات المستودع. المثال التالي لبيانات مصطنعة فقط:

```json
{
  "environment": "local",
  "account_id": "00000000000000000000000000000000",
  "database_id": "00000000-0000-0000-0000-000000000001",
  "database_name": "synthetic-backup-test"
}
```

في الاستخدام التشغيلي، يكتب المسؤول هوية الهدف التي تحقق منها أثناء التصدير، ووقت التقاط النسخة UTC وSHA الكود. يقبل المدقق هويات `local` و`staging` و`production` كبيانات وصفية فقط؛ الاستعادة دائمًا محلية إلى binding مصطنع مستقل. ملف SQL لا يثبت حسابه الأصلي، لذلك يسجل manifest صراحة `identity_source: operator_supplied`. لا تمثل هذه الملفات إثبات هوية سحابية أو توقيعًا رقميًا؛ احفظ الأصل وأدلة التصدير بصورة خاصة وغير قابلة للتعديل المعتاد.

جهّز مجلدًا خاصًا على قرص مشفر. الأداة تطلب صلاحية ملف `0600` حيث يدعمها النظام، لكنها لا تثبت ACL أو تشفير القرص. على Windows جهّز ACL للمستخدم المسؤول وSYSTEM والإدارة المعتمدة قبل نسخ SQL إلى المجلد. SHA-256 بصمة سلامة وليست تشفيرًا.

## إنشاء manifest

```powershell
npm run backup:tools -- manifest --backup C:/PrivateBackups/backup.sql --target C:/PrivateBackups/target.json --captured-at 2026-10-01T08:00:00.000Z --code-sha 0123456789012345678901234567890123456789 --kind manual --output C:/PrivateBackups/manifest.json
```

استبدل مسار المثال والوقت وSHA بالمعلومات الصحيحة. `kind` إحدى `daily` أو `manual` أو `pre_migration`. يتضمن إصدار manifest الأول الحجم والبصمة وسجل migrations وhash المخطط وعدد صفوف كل جدول وبصمة الأعمدة والقيم مع أنواع SQLite. لا يحتوي أسماء الأشخاص أو نصوص الصفوف، لكنه يظل ملف تشغيل خاصًا. لا يقبل SQL عامًا؛ يقبل إنشاء جداول وفهارس وعروض ومحفزات وإدراج صفوف وpragma تأجيل FK المستخدمة في تصدير D1، وأمر `DELETE FROM sqlite_sequence` المحلي الذي يصدره D1 لاستعادة عدادات AUTOINCREMENT. لا يقبل حذف جداول الأعمال. يرفض FK المكسورة وسجل migrations الفارغ أو المكرر. لا يثبت تطابق السجل مع إصدار منشور بعينه؛ هذا جزء من بوابة الترحيل الخاصة بالإصدار.

## تجربة الاستعادة الفعلية

```powershell
npm run backup:tools -- verify --backup C:/PrivateBackups/backup.sql --manifest C:/PrivateBackups/manifest.json --target C:/PrivateBackups/target.json --local-config C:/PrivateBackups/verification-local.json --output C:/PrivateBackups/receipt.json
```

ينبغي أن يكون كل من `verification-local.json` و`receipt.json` جديدًا، وكذلك ملف البيئة الفارغ الذي تنشئه الأداة باسم `verification-local.json.empty.env`. يتحقق الأمر من الهوية المتوقعة والحجم والبصمة وسجل الترحيلات وmanifest قبل تشغيل D1. ينشئ إعدادًا محليًا مصطنعًا، ويستخدم workerd D1 مع `remoteBindings: false` و`persist: false` وملف بيئة فارغ صريح يمنع قراءة `.dev.vars` المجاورة؛ كما يعطّل تحميل `.env` وتضمين متغيرات العملية وجلب معلومات Cloudflare الوصفية عبر `CLOUDFLARE_CF_FETCH_ENABLED=false` أثناء التشغيل، ثم يعيد قيم البيئة السابقة. يستعيد SQL في معاملة واحدة ويثبت المحفزات بعد جميع الصفوف العادية والكبيرة، حتى لا تعيد المحفزات تشغيل تدقيق أو شروط حالية على بيانات تاريخية. يقارن المخطط والأعمدة وجميع القيم والأنواع وتكرار الصفوف وFK. الحالة المحلية مؤقتة ويُغلق runtime عند الانتهاء؛ قد يستخدم runtime ملفات مؤقتة، لذلك يجب أن يكون جهاز التشغيل وأقراصه محميًا. ملف الإعداد يحتوي الهوية المصطنعة فقط. لا تُطبّق ترحيلات جديدة. حدود D1 المحلية أو SQL غير المدعوم تنتج فشلًا واضحًا دون إقرار نجاح أو تخفيف المقارنة.

receipt تربط النجاح ببصمة manifest وبصمة SQL ووقت الاختبار، ولا تحتوي بيانات المدرسة. الأخطاء في CLI تُختصر عمدًا لأن أخطاء SQLite قد تتضمن نص SQL خاصًا؛ الملف الناجح لا يُكتب عند فشل التحقق. لا تستبدل هذه التجربة خطة استعادة خدمة كاملة أو اختبار وصول الملفات الخارجية.

## حداثة الأدلة

```powershell
npm run backup:tools -- status --manifest C:/PrivateBackups/manifest.json --receipt C:/PrivateBackups/receipt.json --target C:/PrivateBackups/target.json --max-backup-hours 24 --max-restore-days 31 --output C:/PrivateBackups/status.json
```

يمكن تكرار `--manifest` و`--receipt` لتقديم السجل المتاح، و`--now` يقبل UTC صريحًا للاختبارات. يقيس الأمر عمر آخر نسخة وعمر آخر تجربة استعادة بصورة مستقلة، ويطابق كل receipt مع manifest الموجودة. استعادة نسخة قديمة اليوم لا تجعل النسخة حديثة. غياب النسخة/التجربة أو تجاوز العمر يعطي exit code **2**؛ المدخلات غير السليمة تعطي **1** والنجاح **0**. لا يعيد هذا الأمر قراءة SQL أو التحقق من وجوده، لذلك تظهر `evidence_only: true` و`files_rechecked: false` دائمًا. أعد أمر verify للتحقق من الملف الحالي. الأوقات المستقبلية وتبديل الهوية وإعادة تقديم manifest نفسها مرفوضة.

## معاينة الاحتفاظ دون حذف

```powershell
npm run backup:tools -- retention --manifest C:/PrivateBackups/manifest.json --target C:/PrivateBackups/target.json --daily 7 --weekly 4 --output C:/PrivateBackups/retention-plan.json
```

الخطة تختار أحدث نسخة في كل يوم من آخر 7 أيام ممثلة في السجل، وأحدث نسخة لكل أسبوع من آخر 4 أسابيع ممثلة فيه؛ حدود الأسابيع تبدأ الاثنين UTC. تبقى كل نسخ `pre_migration` محمية دائمًا. بقية النسخ تصنف `review_candidate` للمراجعة فقط، ولا يعني ذلك أنها آمنة للحذف. لا يوجد أمر حذف أو release تلقائي للحماية، ولا تُحذف نسخة عند إعداد الخطة. يظل قرار الحذف ومراعاة الاحتفاظ المطلوب وسعة الحفظ مسؤولية التشغيل.

## الفحوص والحدود المتبقية

`npm run test:backup-verification` ضمن مصفوفة الانحدار الإلزامية. يشمل استعادة D1 مصطنعة مع Unicode واقتباسات وBLOB وNULL وREAL وINTEGER كبير وصف يتجاوز 360KB، وأرشيف جدول كبير من migration 0048 مع مسودة حضور لاحقة للتأكد من استعادته قبل تثبيت محفزات الحماية. المخطط الكامل يُفحص أيضًا ضمن `test:backup-restore:local` القائم. تشمل الرفض: تلف البايتات، هوية مختلفة، سجل/بصمة غير مطابقين، FK مكسورة، SQL غير ملائم، مسارات داخل Git أو متقاطعة معه، واستبدال الأدلة. تشمل freshness النسخ القديمة وتواريخ المستقبل والربط الخاطئ للأدلة، وتشمل retention حماية ما قبل الترحيل وعدم الحذف.

D1 SQL لا يحتوي R2؛ تسجل الملفات `r2_included/verified: false`. لا توجد أسرار في الأمثلة أو CI، ولا يجب رفع SQL حقيقي أو screenshots خاصة كـCI artifacts. أدوات CI تفحص بيانات مصطنعة فقط. أهداف RPO ≤24h وRTO ≤4h في [بوابة التشغيل](OPERATIONAL_READINESS_GATE.md) تبقى مقترحة حتى قياس النسخ والاستعادة الفعليين وتشغيل التنبيهات.

## دليل قبول نسخة STAGING خاصة — 2026-10-01

اجتازت نسخة SQL خاصة من STAGING بحجم **2,878,129 بايت** أوامر `manifest` و`verify` و`status` و`retention`. أثبتت تجربة D1 المحلية تطابق المخطط والقيم وأنواع SQLite وسجل **52 ترحيلًا** مع النسخة، مع مفاتيح أجنبية سليمة. يشير العدد 52 إلى النسخة الملتقطة قبل ترحيل الحسابات 0052؛ لا يعني أن المصدر رُحّل إلى إصدار الحسابات. بقيت SQL وملفات الإثبات الخاصة خارج Git، ولم تُدرج بيانات مدرسية أو أسرار في هذا التقرير.

هذه النتيجة تؤكد قابلية استعادة النسخة المحددة وصحة الأدوات عليها. لا تتضمن استعادة بعيدة أو ملف R2 أو تفعيل جدولة أو تشفير جديد. فحص `status` يعتمد الأدلة المسجلة، و`retention` معاينة دون حذف. إعداد النسخ الدوري ما زال مؤجلًا بقرار المستخدم.

بعد دمج تغييرات الحسابات 0052 في فرع الأدوات، نجح TypeScript واختبارات الأدوات **13/13**، ثم تجربة النسخ والاستعادة المحلية المتكاملة على **53 ترحيلًا و99 جدولًا** ببيانات مصطنعة. تحقق التطابق الكامل للمخطط والقيم والأنواع وFK، بما فيه صف **360,009 بايت**، وعمل المدقق العام على النسخة نفسها. احتفظت مصفوفة الانحدار بمجموعتي الحسابات والنسخ وأوامر CLI، وتغطي **38 مجموعة و87 ملف اختبار**؛ هذا فحص شمول المصفوفة وليس ادعاء نجاح تشغيل جميع المجموعات على CI.

مرجع إعداد الاستعادة: [Wrangler getPlatformProxy](https://developers.cloudflare.com/workers/wrangler/api/#getplatformproxy)، مع خيارات النسخة المثبتة في package-lock.
